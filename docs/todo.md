# Todo カンバンボード

サイドメニューの「Todo タスク」または `/tools/todo` から利用します。ログインしたユーザー専用のボードです。

## 操作

- 「タスク追加」または各列の「＋」で追加します。タイトル、説明、ステータス、優先度、任意の期限を設定できます。
- カードの「⠿」をドラッグすると移動できます。同じ列の上下移動で優先順、別の列への移動でステータスが変わります。
- 列の上にあるタスクほど先に取り組む順番です。「緊急・高・通常・低」の優先度は別に設定でき、自動ソートはしません。
- カードの本文をクリックすると編集画面が開きます。ステータスの選択や削除もここで行います。カードの上下矢印でも順番を変えられます。
- キーボードでは「⠿」にフォーカスし、Spaceで持ち上げ、矢印キーで移動、Spaceで確定、Escapeで中止します。
- 「ステータス管理」で列の追加・名前変更・色変更を行います。タスクが残る列と最後の列は削除できません。
- スマートフォンではボードを横スクロールできます。カード本文でスクロールし、移動は「⠿」を使います。

変更はCloudflare D1へ自動保存します。保存に失敗した場合は画面に理由を表示し、直前の状態に戻します。複数端末で同時に更新した場合は、古い内容で上書きせず最新状態を読み直します。ほかの端末の表示は再読み込みで更新してください。リアルタイム同期やオフライン編集は未対応です。

## 保存構成

- `shared/todo.ts`: ブラウザーとWorkerで共有するデータ型・選択肢。
- `src/tools/todo/`: 画面、ダイアログ、ドラッグ処理と保存Hook。
- `worker/tools/todo/`: 入力検証・認証後のAPI・D1アクセス。
- `migrations/0003_todo.sql`: `todoBoard` テーブルを追加。
- `GET /api/todo`: 初回のみ「未着手・進行中・完了」を作成して取得。
- `PUT /api/todo`: ボード全体を置換。所有者はセッションの `user.id` を使用し、本文のuserIdは使用しません。送信元・入力・版番号を検証します。

小規模な個人用ボードを想定し、各ユーザーのステータスとタスクをJSONで1行に保存します。1つのSQLで内容と版番号を更新するため、途中だけが保存されることはありません。ユーザー削除時は外部キーのCASCADEでボードも削除します。

上限は30ステータス・500タスク、タイトル200文字・説明4,000文字・ステータス名50文字、送信するボード全体で1MBです。個別タスク検索や大量データが必要になった場合は、追加のマイグレーションで保存構成を見直してください。

## マイグレーションと検証

```sh
bun run wrangler d1 migrations apply my-tools-web-db --local
bun run check
bun run build
```

本番公開前に、対象を確認して `--remote` でもマイグレーションを適用します。認証テーブル・既存ユーザーは変更しません。

2026-11-12にローカル・本番へ `0003_todo.sql` を適用し、Workerへ公開済みです。

Bunテストでは所有者の分離・更新競合・不正入力・並べ替えを検証します。ローカルWorkersとD1でも保存・取得・未ログイン・別ユーザー・不正な送信元・古い版の更新を確認してください。
