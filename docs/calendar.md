# カレンダー

`/tools/calendar` またはサイドメニューの「カレンダー」から開きます。

## 操作と公開範囲

- 月間カレンダーの日付を選ぶと、その日の予定一覧を表示します。「予定追加」で選択日の予定を登録します。
- タイトル、説明、開始・終了日時、公開範囲を指定できます。日時はすべて日本時間で、開始・終了の両方が5分単位です。日をまたぐ予定にも対応します。
- **Private**: 登録者本人だけが閲覧できます。新しい予定の初期値です。
- **Public**: ログイン済みのアプリ使用者全員が、タイトル・説明・日時・登録者名を閲覧できます。インターネット全体への公開ではありません。
- 他人のPublic予定も、編集・削除できるのは登録者本人だけです。管理者にも他人の予定を編集する機能は設けません。
- ドロップダウンの初期値は **Public — 自分の予定＋全員の公開予定** です。自分のPrivate予定も含みます。「自分の予定のみ」では、他人のPublic予定も表示しません。
- 登録者名はアカウントの表示名です。月間カレンダーの予定概要、選択日の一覧、予定詳細で確認できます。スマートフォンの月間セルは件数表示にし、日付を選択した先の一覧で名前を確認します。
- 予定一覧から詳細を開き、自分の予定を編集・削除できます。削除は確認後に行います。

表示条件は画面を開くたびにPublicへ戻ります。予定の変更はD1へ保存します。ほかの端末やユーザーの変更を反映するには「再読み込み」を押してください。リアルタイム同期・繰り返し予定・通知・終日専用の入力は未対応です。

## 実装

- `shared/calendar.ts`: 画面・Worker共通のデータ型と5分単位の日時検証。
- `src/tools/calendar/`: カレンダー画面、日別一覧、詳細フォーム、取得・保存Hook。
- `worker/tools/calendar/`: API・入力検証・D1アクセス。
- `migrations/0004_calendar.sql`: 予定テーブルと所有者・公開範囲別の索引。
- `src/shared/components/Modal.tsx`: Todoとカレンダーが共有するダイアログ。

`/api/calendar` は全メソッドでセッション確認を必須にし、応答に `Cache-Control: no-store` を付けます。Publicも未ログインでは取得できません。

| メソッド | 操作 |
| --- | --- |
| GET | `from` / `to` の半開区間と `scope=public` または `mine` で取得（省略時public） |
| POST | セッションのユーザーを登録者として作成。本文のuserId・登録者名は採用しない |
| PUT | id・revisionを指定して本人の予定を更新 |
| DELETE | id・revisionを指定して本人の予定を削除 |

閲覧範囲はSQLで絞り込みます。他人のPrivate予定を取得してからブラウザーで隠す方法は使いません。公開データにもメールアドレスや内部の所有者IDは含めず、登録者名と本人の予定かを返します。

更新・削除では所有者とrevisionを条件にします。Publicの予定でも、別ユーザーの変更要求は404にし、本人の古い版からの要求は409にします。保存失敗時はダイアログを閉じず、入力を保持します。競合時は閉じて最新状態を再取得してください。

一覧の期間は最大62日・500件です。500件を超える場合は省略して成功扱いにせず、エラーを表示します。タイトルは200文字、説明は4,000文字、書き込み本文は32KBまでです。日時は `YYYY-MM-DDTHH:mm` 形式の日本時間で保存し、端末のタイムゾーンによるずれを防ぎます。

## 検証・公開

```sh
npx wrangler d1 migrations apply my-tools-web-db --local
npm run check
npm run build
```

公開前に `--remote` でもマイグレーションを適用します。認証・Todoテーブルは変更せず、カレンダー専用テーブルを追加します。

2026-11-12にローカル・本番D1へ `0004_calendar.sql` を適用しました。

テストでは別ユーザーからのPrivate閲覧不可、Publicの登録者名、本人のみのフィルター、他人による編集・削除の拒否、公開解除、更新競合、5分単位、日をまたぐ予定を検証します。ローカルWorkersとD1でも同じ公開範囲を確認してください。
