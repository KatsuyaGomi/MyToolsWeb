# ユーザーのグループ

## 利用方法

管理者本人が「アカウント管理」下部の「グループと所属の管理」を開きます。

1. グループを作成します。名前は1〜60文字、最大30グループです。
2. ユーザーの「所属を変更」を押し、所属先をチェックして保存します。複数選択できます。
3. 名前の変更やグループの削除もこの画面で行えます。削除には確認が必要で、全メンバーの該当所属も解除されます。

管理者判定は、DBの `admin` ロールとSecret `ADMIN_EMAIL` の一致を使います。一般ユーザーや管理者ロールだけの別アカウントは、APIの直接呼び出しでも所属を設定できません。新しいユーザー・既存ユーザーとも、自動的にグループへ割り当てません。管理画面に表示する対象は既存のユーザー一覧に合わせて最新100人です。

## カレンダーの閲覧範囲

| 対象 | 閲覧できる人 |
| --- | --- |
| Private予定 | 登録者本人だけ |
| Public予定 | 本人と、登録者の所属グループのどれかに所属するログインユーザー |
| 未所属のユーザーのPublic予定 | 本人だけ |

Publicは**登録者の所属先すべて**に共有します。予定ごとの共有先選択は行いません。共通するグループが複数あっても予定は1件だけ表示します。管理者も、他人の予定を閲覧するには共通グループが必要です。管理者だから全予定を閲覧できる例外はありません。

所属変更は既存のPublic予定にも反映します。ユーザーを追加すると、そのグループのPublic予定を閲覧できるようになり、そのユーザー自身のPublic予定も共有されます。最後の共通グループを解除すると相互の閲覧ができなくなります。本人の予定やPrivate予定の扱いは変わりません。

閲覧条件は毎回DBで判定します。ブラウザーの表示更新には再読み込みが必要です。取得済みの内容を端末から回収する仕組みやリアルタイム通知はありません。

## 実装・API

- `migrations/0005_groups.sql`: userGroup / groupMembership / groupSettingsを追加。
- `shared/groups.ts`: グループ・所属・設定版の共通データ型。
- `worker/groups/`: 所有者の管理者判定、入力検証、D1での設定更新。
- `src/app/groups/`: 管理画面、複数所属のダイアログと取得・保存Hook。
- `worker/tools/calendar/repository.ts`: 所属の存在をEXISTSで確認し、他人のPublicを絞り込む。

| API | 操作・権限 |
| --- | --- |
| GET /api/groups | 認証済み本人の所属ID・名前だけを取得 |
| GET /api/admin/groups | 管理者本人が全グループ・設定版を取得。userIdクエリー（最大100人）で対象の所属も取得 |
| POST /api/admin/groups | 管理者本人がグループを作成 |
| PUT / DELETE /api/admin/groups/:id | 管理者本人が名前変更・削除 |
| PUT /api/admin/users/:id/groups | 管理者本人がgroupIds配列で所属を一括置換。空配列は全解除 |

すべてのAPIで認証とno-storeを維持します。変更には正しいOriginと取得時のrevisionが必要です。設定の変更はD1のbatch内で版番号と一意の操作IDを確認し、競合時には409を返します。重複名や外部キー違反などで失敗すると、所属の削除や版番号の更新もロールバックします。

## ブランチと本番反映

この機能は `codex/user-groups` で開発します。本番へはまだ反映していません。`0005_groups.sql` はローカルD1のみ適用済みです。

本番反映時は、対象DBを確認して**先に**マイグレーションを適用し、その後mainへのマージ・デプロイを行います。新しいSQLがグループテーブルを参照するため、適用前のWorker更新は避けてください。

```sh
bun run wrangler d1 migrations apply my-tools-web-db --remote
```

既存のユーザー・予定は削除しません。移行直後は全員が未所属となるため、他人のPublic予定は見えなくなります。管理者が必要な所属を設定して共有を開始してください。グループ名・メンバーをmigrationに固定せず、実データをGitへ保存しません。

ローカルでの実行は `bun run wrangler d1 migrations apply my-tools-web-db --local`、検証は `bun run check` と `bun run build` です。所有者の管理者限定、複数所属、未所属、所属解除、グループ削除、更新競合とカレンダーの分離を確認します。
